# PageCounter

Counts the pages of Office documents by rendering them with the optional
`OfficeAgent.Rendering` package, and shows what a renderer adds that OfficeAgent's structural
inspection cannot: inspection reads text, tables, comments and revisions, but pagination only
exists once something lays the document out.

The sample has two modes:

1. **Rendering (the default).** `LibreOfficeDocumentRenderer` converts the file to PDF with
   LibreOffice and rasterizes each page with Poppler's `pdftoppm`; the page count is the number
   of page images. It accepts `.docx`, `.pptx` and `.xlsx`.
2. **`--openxml`.** Reads a `.docx` with the Open XML SDK and starts no process. It reports the
   `Pages` value Word records in the extended properties (`docProps/app.xml`) when it saves,
   which is Word's count at that save and goes stale after any edit made without Word. A file
   with no such value, such as one generated by code, gets an estimate from the body: one page
   per 50 paragraphs plus one per 3 tables, and at least one. The output says which it is.

## Prerequisites

- .NET 10 SDK (the repository's `global.json` selects it)
- For the default mode, LibreOffice and Poppler:

  ```bash
  # Ubuntu/Debian
  sudo apt-get install libreoffice poppler-utils

  # macOS (Homebrew)
  brew install --cask libreoffice
  brew install poppler
  ```

  On Windows, install LibreOffice and a Poppler build. If `soffice` and `pdftoppm` are not on
  `PATH`, set `SOFFICE` and `PDFTOPPM` to their full paths.

## Run

From the repository root:

```bash
dotnet run --project samples/PageCounter -- samples/documents/services-agreement.docx
```

Pass several files to count each, and add the options anywhere on the line:

```bash
dotnet run --project samples/PageCounter -- report.docx deck.pptx model.xlsx --quiet
dotnet run --project samples/PageCounter -- samples/documents/services-agreement.docx --openxml
```

| Option | Effect |
| --- | --- |
| `--openxml` | Read Word's recorded count, or estimate one, instead of rendering. `.docx` only |
| `--quiet` | Print only `Page count: N` for each file, and render or read errors. A missing file is then reported only by the exit code |

Run with no file to print the usage. Every render uses fixed limits: 144 DPI, a 120-second
timeout, 100 MB of input, 500 MB of page images, 10,000 pages and a 512 MB working set per
renderer process.

## What you should see

With LibreOffice and Poppler installed, the default mode prints the page count, the render time
and the size of the page images, in this shape:

```text
Processing: services-agreement.docx
  File size: 3.79 KB
  Rendering with 144 DPI, 120s timeout...
Page count: <pages>
  Method: LibreOffice rendering
  Accuracy: Very High (visual rendering)
  Rendering completed in <ms> ms
  Total image data: <size>
  Average page size: <size>
```

The page count, timing and sizes depend on the document and the LibreOffice version.

Without them, the renderer reports `renderer-unavailable` and no count:

```text
Processing: services-agreement.docx
  File size: 3.79 KB
  Rendering with 144 DPI, 120s timeout...
Rendering failed: renderer-unavailable
  Details: A configured renderer executable was not found.
```

The sample contract was generated by code and records no `Pages` value, so `--openxml` prints
the estimate:

```text
Processing: services-agreement.docx
Page count: 1
  Method: OpenXML SDK, estimated from the body (no Pages value recorded)
  Accuracy: Low (one page per 50 paragraphs plus one per 3 tables)
  External dependencies: None
```

A file Word saved reports Word's count instead:

```text
Page count: 3
  Method: OpenXML SDK, the Pages value Word recorded in docProps/app.xml
  Accuracy: Medium (Word's count when it last saved the file)
```

The process exits with 2 when no file is given, and with 1 when a file is missing, reading it
throws, or the render fails, including a failure code such as `renderer-unavailable`.

## Things to know

- The count is LibreOffice's pagination. Word can paginate the same file differently,
  especially with unresolved fields, pending tracked changes, missing or embedded fonts, and
  complex tables. Pin the LibreOffice and Poppler versions wherever counts must stay comparable.
- The renderer starts external processes, so a count takes seconds, not milliseconds; the
  first render after start-up also starts LibreOffice.
- The working-set limit is a process-level guard. For documents from untrusted callers, run the
  renderer inside an OS boundary such as the
  [sandboxed renderer reference](../../deploy/renderer/README.md).

See [visual rendering](../../docs/rendering.md) for the renderer's options, checks and failure
codes.
